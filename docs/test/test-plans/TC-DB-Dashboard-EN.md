## How to Read Reports and Test Data

- **Primary Learner** is the account currently being tested on the Dashboard. **Other Learner** only appears in security test cases to prove data does not leak across accounts. This is a role name, not an actual account name.
- Plans, concepts, and sessions in each test case are referred to by their **business role** — e.g., "plan with an active deadline," "archived plan," "untested concept" — instead of the mock data IDs in the script. When technical verification is needed, system fields/IDs are enclosed in code formatting in the Notes section.
- The testing time is fixed at **10:00, Wednesday 2026-08-05 (Vietnam Time)**, unless otherwise stated by the test case. "This week" starts at 00:00 Monday Vietnam time.
- "Relationship A → B" is read as **A is a prerequisite concept for B**. "Phiên vấn đáp" is Interview Session; "phiên học tập trung" is Focus Session.
- "Total study time" currently only calculates completed Focus Sessions, following the current Dashboard implementation. Technical fields such as `mastery_score`, `active`, and `archived` are only mentioned when verifying data rules.
- For Use Case content without exact wording, layout, or response time requirements, the evaluation is based on business logic and the approved UI, without introducing extra criteria.
- The **Actual Result**, **Status**, **Notes**, and **Comments** fields are standalone conclusions: readers do not need to open the script to understand the data, the results, or pending decisions.
- When an API or technical data is a test criterion, the **Expected Result** and **Actual Result** cells retain the field names, values, and response codes to be used directly during implementation/cross-checking; the description and notes explain their business significance.
