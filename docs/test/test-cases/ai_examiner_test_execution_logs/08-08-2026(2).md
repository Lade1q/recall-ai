## 📍 CF-01: Happy Path - Trả lời tốt cả 3 lượt

**Concept đang hỏi:** `Linear Search without a Sentinel`

**Lượt 1:**

- **AI Hỏi:** `In a linear search without a sentinel, what value is returned by the function if the search element x does not match any of the elements in the array?`
- **User Trả lời:** `In a standard linear search without a sentinel, if the search element x does not match any elements in the array, the function typically returns a special value to indicate a 'not found' state. In most implementations (like C++, Java, or Python), this is represented by returning -1, since valid array indices always start from 0. By returning a distinct negative value, the algorithm ensures that the calling function can reliably distinguish between a successful search (which returns a valid index >= 0) and an unsuccessful one.`
- **Kết quả (Network Tab/UI):** Verdict: `deep` | Score: `1.00`

**Lượt 2:**

- **AI Hỏi kế tiếp:** `Why does each iteration of a linear search without a sentinel require two comparisons, and what specific checks do those two comparisons perform?`
- **User Trả lời:** `Each iteration of a standard linear search requires exactly two comparisons to ensure both correctness and memory safety. The first comparison checks if the current index is still within the valid bounds of the array (e.g., i < n) to prevent out-of-bounds errors. The second comparison checks if the element at that current index matches the target value (e.g., arr[i] == x). Because a standard linear search lacks a guaranteed stopping marker at the end (a sentinel), it cannot safely assume the loop will terminate before reaching the end, thus necessitating both checks on every single pass.`
- **Kết quả (Network Tab/UI):** Verdict: `deep` | Score: `1.00`

**Lượt 3:**

- **AI Hỏi kế tiếp:** `In the average-case analysis of a linear search without a sentinel, the total average number of comparisons across all iterations is given as 2 × (1 + 2 + ... + n) / n = n + 1. Mathematically explain how this formula is derived based on the assumption of a uniform distribution for finding element x.`
- **User Trả lời:** `Assuming a uniform distribution, the target element x has an equal probability (1/n) of being found at any index i from 1 to n. To find x at position i, the algorithm must perform i iterations. Since each iteration requires exactly two comparisons (one for boundary checking and one for value matching), finding x at position i takes 2*i comparisons. The average number of comparisons is the sum of the comparisons for each possible position multiplied by their probability: sum from i=1 to n of (2*i * 1/n). We factor out 2/n to get (2/n) * (1 + 2 + ... + n). Using the arithmetic series sum formula, the sum of 1 to n is n*(n+1)/2. Plugging this back in: (2/n) * (n*(n+1)/2). The 2's cancel out, and the n's cancel out, leaving precisely n + 1 as the average number of comparisons.`
- **Kết quả (Network Tab/UI):** Verdict: `deep` | Score: `1.00`

**Kết luận State Machine:** Hệ thống có tự động dừng lại sau lượt 3 không? `Có. Hệ thống dừng lại chuẩn xác sau 3 lượt deep.`
**Trạng thái Kịch bản:** `PASS`
