## UC-05: Tạo kế hoạch ôn tập mới (SP-01)

**Endpoint chính:** `POST /api/v1/plans`

**Môi trường:**

- Base URL: `http://localhost:3001/api/v1`
- Auth: JWT Bearer token — lấy từ `POST /api/v1/auth/login`
- Mock AI: `USE_MOCK_AI=true` trong `.env` server
- DB: Test DB riêng — reset bằng `npm run test:seed` trước mỗi lần chạy
- File mẫu: `sample_lecture.pdf` (~2MB), `large_file.pdf` (~15MB), `document.docx`

| **Mô tả**                | Upload file PDF kích thước vượt giới hạn 10MB. Multer từ chối ngay tại middleware, `errorHandler.ts` chuyển `MulterError.LIMIT_FILE_SIZE` thành HTTP 400. | **Các bước thực hiện**   | 1. Gửi `POST /api/v1/plans` với `name = "Ôn thi Giải tích"`, `deadline = "2026-12-31"`, `file = large_file.pdf` (15MB)<br>2. Kiểm tra HTTP status và response body<br>3. | **Kết quả mong đợi**     | Sub-case **02a** (15MB):<br>- HTTP Status: **400 Bad Request** ← **(không phải 413)**<br>- `"success": false`<br>- `error.code = "FILE_TOO_LARGE"`<br>- `error.message` đề cập giới hạn 10MB<br>- DB: **không** có bản ghi nào<br><br>Sub-case **02b** (đúng 10MB):<br>- HTTP Status: **201 Created** |

| **Trạng thái**           | Pass (2/2)                                                                                                                                                                                                                                                                                            |
| **Ghi chú**              | HTTP 400 (không phải 413) vì `errorHandler.ts` bắt `MulterError` và map thành 400. | **Nhận xét**             | Việc giới hạn dung lượng được xử lý chính xác tại middleware, ngắt kết nối ngay lập tức giúp tiết kiệm băng thông. Bài test boundary cho file đúng 10MB vượt qua chứng tỏ logic code chặt chẽ (không bị lỗi off-by-one).                                                                              |
